작성: **2026-11-08 (Asia/Seoul)**. 최초 문서화 이후 사용자가 구현을 승인했다. **현재 적용·검증 상태는 [구현 기록](incidents/2026-11-08-state-reference-alignment.md)을 따른다.** 아래 조사 결과와 미실행 계획은 구현 전 기준을 보존한 것이다.

## 2. 수리 범위와 보존 계약

후속 구현의 목표는 다음으로 한정한다.

1. 현재 주 ID·경계·프로빈스 소속·해안 속성·전략 지역·보급망·지도 배치를 유지한다. `history/states/`, `map/`를 고쳐 코드 오류를 덮지 않는다. 시작 인구·산업·자원·승점·카테고리도 유지한다.
2. 잘못된 숫자 참조, 현재 부모 주와 맞지 않는 프로빈스 효과, 원래 지역에서 빠진 후속 주 목록, 관련 설명을 문맥별로 정렬한다. 국가 이력의 수도 참조는 지도 변경과 구분한다.
3. 고정 수량 보상은 원래 총량을 보존한다. 부모 주가 나뉘었다고 공장·슬롯·자원·승점·요새 묶음을 양쪽에 복제하지 않는다. 기존 추가 혜택·DLC 대체 보상도 유지한다.
4. **지리적 범위 복구와 산업 보상 증액을 구분한다.** 옛 경계·의도 대응에 근거해 통제·이전·코어 목록은 길어질 수 있다. 그러나 지역 이름·현재 소유·코어만으로 모든 누락 후보의 원래 의도를 확정하지 않는다. 기존 인구·공장을 영토와 함께 이전하는 것과 새 건물 생성은 다르다. 지도와 직접 보상 수치를 보존해도 착수 난도·수혜국 인력/산업·저항 등 실제 밸런스가 완전히 같지는 않다.
5. 착수·유지·취소·완료·우회·강조·지급 위치를 각각 대응시킨다. 부모 scope만 바꾸는 수리와 소유·통제 조건을 넓히는 변경은 별도 판단이다. 숫자 전체 치환은 하지 않는다.
6. 영토 이전과 코어 부여도 별개다. INS 소유인 새 주가 INS 코어라는 뜻은 아니며 지역 태그 코어를 보존한다. 인도차이나 사건이 원래 주던 VIN 코어를 결정 경로에 자동 복사하지 않는다. 제거한 간도·안둥·헤이허를 큰 현행 부모 주 전체의 claim/core/transfer로 되살리지 않는다.
7. 중점·결정·이벤트·표식·현지화 키와 저장 내 완료 이력을 보존한다. ID 보존만으로 진행 중 효과의 저장 호환을 보장하지 않는다. 소급 코어·완료 보상·일회 결정 재개방은 별도 정책 없이는 추가하지 않는다.
8. 바닐라·Workshop 설치 파일은 수정하지 않는다. 상속 코드의 수리는 저장소의 최소 호환 코드로 준비하되, 디렉터리별 등록·중복 ID·동명 파일 우선순위를 먼저 확인한다. 근거 없는 `replace_path`, 전역 데이터베이스 전체 복사, 미확인 재정의 구문을 도입하지 않는다.
9. 중점 배치·기간·비용·AI 가중치·정치 경로·업로드 정체성은 보존한다. 해안 위치·수도·섬 포함 의도가 모호하면 판단 항목으로 남긴다.

## 3. 판정과 원인 구분

각 항목의 **관측 사실**과 **게임에서의 영향**을 따로 판단한다.

- `CONFIRMED`: 명시적 ID/목록, 현재 부모 주, 비해안 여부, 두 블록의 불일치를 소스로 확인했다.
- `STRONGLY_SUPPORTED`: 설명·기존 대응·호출 관계가 수리 의도를 지지하지만, 설계 범위나 엔진 처리가 남았다.
- `UNPROVEN`: 효과 무시·보상 미지급·오류 로그·최종 영토 분배·저장 영향 등 이번에 실행하지 않은 결과다.

아래는 **구현 전** 코드상 불일치 대장이다. 모든 행을 재현된 게임 결함이나 이번 한국 분할의 회귀로 합산하지 않는다. 당시 상태는 모두 미수리였다. 현재 적용 여부는 구현 기록에서 따로 관리한다. 행 번호는 2026-11-08 최초 읽기 기준이며 ID·주변 블록을 함께 따른다.
