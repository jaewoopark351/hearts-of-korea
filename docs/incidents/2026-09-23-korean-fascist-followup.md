## 로그 비교와 진단 경고

실행 전 기준 `error.log`는 130줄, 시간·게임 날짜만 정규화한 고유 메시지 41종이다. 파일·엔진 소스의 행 번호도 별도로 정규화하면 35종이다. 이 두 기준을 구분하고 메시지의 실제 파일명·수치·원인을 지우지 않는다.

완료된 세 강제 진단은 각각 135줄이다. **새 경고는 실행마다 1종·7회**이며 원문은 `scopedvariable.cpp:560`의 `production_speed_industrial_complex_factor` 동적 토큰 동기화 경고다. 임시 진단은 `modifier@production_speed_industrial_complex_factor`로 합산 수치를 읽으며, production 국민정신은 일반 modifier 정의를 사용한다. 아래 진단 없는 동일 production 로드에서는 경고가 없었으므로 이번 실행의 진단 경고와 production 로드 결과를 분리할 수 있다. 강제 진단의 경고 원문과 발생 수는 그대로 보존하며 이 세 실행을 “신규 오류 0건”으로 보고하지 않는다.

그 외 신규 메시지는 없었다. 기준 로그에 있던 `random.log` 이름 변경 실패 두 줄은 이 세 실행에서는 나타나지 않아 전체 줄수 차이는 +5다. 새로운 경고 7줄과 기존 오류 2줄의 감소를 상쇄하여 경고가 없어진 것으로 계산하지 않는다. `runtime-log-audit.json`은 시간만 제거한 비교와 행 번호까지 제거한 비교, 발생 횟수 차이, 새 메시지 원문을 모두 보존한다.

## 진단 없는 새 게임 로드

`clean-01`은 임시 진단을 제거하고 전체 프로세스를 새로 시작한 Korea 새 게임 로드다. `run.json`은 `Completed = true`, `Reason = clean-newgame-loaded`, 34.7초를 기록한다. 즉시 보상 검사 자체가 없으므로 **0 PASS / 0 FAIL은 보상 검증 통과 건수가 아니다**. 해당 runner가 공통으로 남긴 `ValidationScope` 문자열은 강제 보상용 일반 문구이며, 이번 실행의 범위는 시나리오·완료 사유와 실제 진단 부재로 구분한다.

`system.log` 기준 버전은 **1.19.3.0.c01a**, 체크섬 **81ce**, DLC 36개·모드 1개다. `error.log`는 128줄, 시간만 정규화한 고유 메시지 40종이며 행 번호까지 제거하면 34종이다. 기준 대비 새 메시지는 두 정규화 방식 모두 **0종**이고 동적 토큰 경고도 0회다. 기준의 로그 이름 변경 오류 두 줄만 없어졌다. 조용한 신규 로그는 정상 35일 진행·실제 UI·장기 AI·저장·멀티플레이의 증거가 아니다.

이 실행 역시 기존 저장·플레이세트·런처·production 해시가 유지됐다. 종료 후 설정에는 게임이 추가한 `graceful_exit=no`만 달라졌다. 이후 UI 게임을 GUI로 종료한 뒤 원본 설정으로 돌아왔음을 별도 대조했다. 아래 UI 종료·복구 기록과 구분하며, 최초 로그 감사 시점에는 진행 중인 UI 실행 로그를 포함하지 않았다.
