## 원인과 수정

`CONFIRMED`: 기존 직접 `offset` 네 블록은 이동 `(0,0)`이고 공산 루트에는 이동 블록이 없었다. 숨김만으로 남은 구역의 좌표를 압축하도록 작성되어 있지 않았다. 절대좌표를 상대좌표 표기로 바꾸기만 해서는 해결되지 않는 최종 거리 문제다.

운영 파일은 `common/national_focus/korea.txt` 하나이며 공화국·공산·민주·파시·왕정 진입 중점 다섯 블록의 이동과 인접 기여 주석만 변경했다.

|---|---:|---|---|---|
| 공산 | −5 | (79,2) | (79,0) | x0~95 / y0~19 |
| 민주 | −35 | (92,2) | (92,0) | x0~123 / y0~24 |

| 비동맹 | −101 | (85,0) | 기존대로 숨김 | x0~103 / y0~19 |

¹ 고정 구역 133개와 선택 노선의 모든 상대 자손을 포함한 정적 모델이다. 표시 범위와 엔진 스크롤 한계는 같은 개념이 아니다.

공화국 이동은 노선별 세 블록으로 분리하고 서로 다른 정치 진입 완료가 중복되면 적용하지 않도록 했다. 민주·파시·왕정의 기존 HIDE·자기 완료 조건은 그대로이며 공산에도 같은 시점을 적용했다. 선택·진행 중에는 이동하지 않고 SHOW는 항상 기존 기본 배치다. 기존 완료 보상의 배치 갱신 효과 다섯 개를 유지한다.

상대 자손에는 이동 블록을 추가하지 않았다. 설치본 일본 `JAP_okadas_military_purge_speech`와 오스트리아·체코의 공통 진입은 복수 이동 블록의 문법 근거다. 일본 `JAP_strengthen_civilian_government`와 `JAP_revere_the_emperor_destroy_the_traitors` 아래 상대 자손은 기준점 이동 구조의 근거다. 설치본 효과 문서는 `mark_focus_tree_layout_dirty`의 COUNTRY 범위 트리 새로고침을 설명한다. 한국 트리의 실제 상속·렌더링은 별도 실행 검증 대상이다.

## 실행 검증과 남은 한계

실행 중 사용자 게임에는 입력·종료를 수행하지 않았다. 사용자가 직접 종료했다고 응답한 뒤 기존 프로세스가 없음을 확인하고 별도 새 게임을 로드했다. 기준 로그와 저장 13개 목록·해시를 미리 보존했다.

- 적용 소스의 새 실행은 `1.19.3.0.c01a / c7e5`, build `25205862`, DLC 36개·HoK 1개였다. 별도 임시 진단 코드 없이 HIDE·한국·일시정지·AI 중지 조건으로 실행했다.
- 약 39.90초에 `1936.1.1.12` 새 게임 시작과 `End RestoreDeviceObjects`를 확인했다. 직전 실행 로그 및 보존 기준 로그와 비교한 신규 정규화 오류는 **0건**이었다.
- 검증용으로 연 PID만 종료했다. 현재 운영 파일 29개와 저장 13개, 플레이세트·런처 정의는 전후 해시가 같았다. 게임이 `settings.txt`에 자동 추가한 `graceful_exit=no` 한 줄은 전후 원문을 보존하고 해시 조건을 확인한 뒤 복원했다. 복원된 설정은 실행 전 SHA-256 `8fdacbf3f1ace0881a7e8655a98fb33095a6c39f4a6e2450f020abb7212432fd`와 일치한다. 사용자 프로세스는 종료하지 않았다.
- 최종 보존 확인은 운영 파일 29개·저장 13개·설정/플레이세트/런처 3개 모두 해시 변경 0, 남은 게임 프로세스 0이었다. 복원 과정과 가까운 시점에 사용자가 `settings.txt` 쓰기에 대한 AVG 보호 알림을 공유하고 직접 앱 허용을 선택했다. 에이전트는 보안 설정을 변경하지 않았으며 추가 사용자 설정 쓰기를 중단했다. 앞선 파일 읽기 오류는 파일 사용 중이라는 내용이었고 AVG가 그 오류의 원인이었는지는 확인하지 않았다.
- 현재 컴퓨터 제어 도구의 native pipe가 연결되지 않아 실제 화면 검사는 수행하지 못했다. 해상도·GUI 배율에 따른 화면 검수도 하지 않았다. 로드 성공·오류 비교는 이동의 실제 적용이나 화면 품질을 증명하지 않는다.
