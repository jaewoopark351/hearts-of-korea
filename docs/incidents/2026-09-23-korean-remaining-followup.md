보완한 `projects-02`는 사례마다 이전 지역 변동치를 정리하고 즉시 이벤트 경계를 거친 뒤 빈 상태와 기준값 0을 확인한다. 실제 사업의 기대값을 올려 실패를 덮지 않았으며 147 PASS / 0 FAIL이다. 여러 정책의 누적 효과는 별도 중점 보상 검사와 구분한다.

### 영토 상실 준비 실패

`lifecycle-control-01`에서는 UI로 M1 사업을 시작하고 정치력 500→350 및 90일 표시를 확인했다. 합성 지배권 상실 직후 조건은 성립했고 일일 진행에서 II와 기간제 변동치가 제거되는 것도 관측했다. 그러나 세 번의 일일 관측 뒤 자동 취소 확인과 상실 조건 지속 확인이 모두 실패했다. 따라서 **4 PASS / 2 FAIL을 자동 취소 성공이나 생산 코드 결함 확정으로 해석하지 않는다.** 이 실행은 공통 대기시간의 실제 90일 만료·재착수까지 도달하지 않았다. 최종 한국어 툴팁과 UI 최초 비용 관측은 이 준비 실패와 별개로 유효하다.

후속 `lifecycle-control-02`는 실제 상실 조건을 유지할 수 있도록 진단 준비만 보완하고 production은 변경하지 않았다. 15 PASS / 0 FAIL로 자동 취소·제도 제거·탈환 후 비자동 복구·90일 대기 만료·UI 비용을 지불한 재착수와 제도 복구를 확인했다. 최초 실패 로그는 보존하며 성공 결과로 덮어쓰지 않는다. 두 실행 모두 사용자 저장을 변경하지 않았다.
